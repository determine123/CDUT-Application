# 选导师与科研匹配

> 整理：2026-10-03。通用建议、个人经历与政策分开阅读；当年官方文件优先。

先看问题和训练方式，再看院校标签。读团队近期研究，了解方法、数据和自己的基础是否有交集。

向不同年级成员了解指导频率、资源、毕业任务、协作、去向和实习安排。区分个人感受与正式规则，不公开未经授权的聊天。

联系邮件简短说明背景、项目、研究兴趣与申请年份，附清晰简历。不群发同一封长信、不夸大能力，也不把回复当录取承诺。

有机会时尝试范围小的研究任务，观察反馈与工作方式是否适合自己。重要培养条件直接沟通并核对正式文件。

## 联系前完成一次小范围阅读

从院系或团队公开页面确认研究方向与联系方式，查看资料日期，选少量与自己兴趣相关的近期工作。先弄清研究的问题、输入或数据、方法和验证方式，再写自己能理解的部分与尚需学习的基础。没有读懂时，可以明确提出具体疑问，不假装已经掌握整条研究路线。

把“想做人工智能”细化为一个可讨论的问题，例如对某类数据上的误差分析感兴趣，或想了解一项方法在另一约束下是否适用。兴趣还在探索时，说明探索过程和已有尝试即可；研究方向相似不等于已经具备团队所需能力。

## 联系内容可以怎样组织

以下是结构示例，需按本人经历和团队要求改写，不直接复制成批发送。

```text
主题：〔申请年份与路径〕科研方向咨询 — 〔姓名或公开使用的称呼〕

老师您好：
我是〔学校、正式专业、预计毕业时间〕的学生，计划通过〔申请路径〕申请。
我阅读了您团队的〔具体工作或公开方向〕，目前理解到〔具体内容〕，
希望进一步了解〔一个明确问题〕。

我在〔课程、项目或研究任务〕中负责〔本人动作〕，完成了〔已验证结果〕；
目前仍需补充〔相关基础或不足〕。
想咨询团队是否适合我进一步了解，以及下一步应按哪一正式流程准备。

附：简历或公开作品链接（仅附自己有权分享的内容）。
感谢您的时间。
```

核对称呼、申请年份、项目名称和附件后再发送。没有回复不等于拒绝，也不能据此判断老师的指导方式；若对方给出跟进时间，按其安排处理。老师愿意交流、愿意指导小任务与正式招生结果分别记录。

## 和在读同学交流时问具体过程

可以围绕最近一次真实任务提问，而不是只问“导师好不好”：

- 一个新任务通常怎样确定范围？卡住时通过什么渠道获得反馈？
- 讨论前需要准备什么，反馈后怎样确认下一步？
- 代码、数据和设备如何申请，复现实验需要哪些基础？
- 团队协作怎样分工，成果中的个人贡献如何说明？
- 课程、科研和其他安排发生冲突时，通常怎样沟通？

让对方只分享愿意公开或私下讨论的范围，不索取他人隐私、内部数据或保密材料。同一团队不同年级、项目与指导者的情况可能不同；将具体事实、个人评价和正式培养要求分开记录。出现矛盾信息时，把问题带回相关负责主体核实，而不是挑选更符合自己期待的说法。

## 尝试任务前先确认范围

一次小任务最好有明确问题、输入材料、可交付结果、讨论时间和验证方式。例如复现一个公开示例时，说明采用的版本、是否允许修改、需要报告哪些结果，以及遇到资源不足时怎样反馈。自己可以投入的时间和已有能力也提前说明。

核对数据和代码的使用许可、成果公开范围及协作贡献的记录方式，不因参与准备任务就把团队成果写成自己的独立研究。任务结束后评价自己能否理解问题、接受反馈和持续推进，也观察安排是否清晰；一次任务的体验不保证未来所有阶段都相同。

## 保存仍需确认的问题

用私人笔记记录团队、资料来源、交流日期、已确认安排、个人感受与未知项。培养年限、毕业要求、资助或调整渠道等事项，回到适用的正式文件核对。对于只能由具体团队解释的安排，记录谁确认了什么及适用范围，不把口头讨论推广成学校政策。

比较多个机会时，可使用[录取决策记录](../planning/decision-review.md)；进入研究生阶段后，参考[过渡准备](../graduate/transition.md)。本章是通用沟通方法，不提供未经亲历者确认的团队排名或个人评价。
