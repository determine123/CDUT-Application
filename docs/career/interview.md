# 面试准备与结果复盘

> 整理：2026-10-03。通用建议、个人经历与政策分开阅读；当年官方文件优先。

把职位要求转成基础、项目追问、编程、分析和协作问题，先确认面试形式。

项目讲清目标、选择、替代方案、个人贡献、失败和验证。行为题使用真实场景，没有直接经验就说明相近经历。未知条件先澄清，展示推理与检查过程。

每轮记录确实问过的问题与不足，区分自身体验和公司整体政策。不泄露禁止公开的内容，不伪造生产经验。

收到机会后比较内容、地点、合同主体与学习空间。不能履行到岗承诺时及时沟通，正式条件按正式材料核对。

## 用职位要求组织准备

把一条岗位要求改写成一个可练习问题。例如，要求理解某类系统时，先问自己能否解释数据从输入到输出的路径、关键约束和失败处理。为问题准备已有经历、能说明的代码或实验，以及尚不熟悉的部分；没有相应经历时承认缺口，再补基础练习。

优先准备简历上已经写出的内容。技术名词出现得越多，越需要能够说明在哪里实际使用、为何选择和如何检查。阅读过某项技术与实际实现过应分开表达。

## 练一次完整的项目追问

选一个项目，用简短开场解释问题、个人工作与结果，然后让同学逐层追问：

1. 为什么选这个问题，最初的约束是什么？
2. 你自己改了哪部分，原有实现和团队工作占哪些部分？
3. 为什么采用这个方案，比较过什么替代方案？
4. 什么输入会失败，发现问题后怎样定位？
5. 结果如何验证，哪些情况还没有验证？

开场不必塞进所有细节；追问时能把证据拿出来更重要。回答涉及不能公开的内容时，说明边界并使用获准公开的抽象描述。[项目证据](project-proof.md)提供演示和验证准备方法。

## 遇到不会的问题

先确认题目条件，再说自己知道的部分。如果需要推导，可以说明正在采用的假设，并检查结论是否符合边界。确实不知道时直接说明，不把猜测说成已验证事实；面试后再查可靠资料或做实验。

编程或分析任务先用一个小例子检查理解，再考虑异常输入、复杂度或限制。具体是否可以使用文档、网络或工具，以面试要求为准，提前确认，不默认可以借助 AI 作答。

## 复盘记录哪些内容

私下记录问题所属主题、自己的回答、缺少的依据和下一次练习动作。将“我回答不完整”“对方明确反馈”“我猜测被拒原因”分开写。没有反馈时不要替招聘方下结论，更不能以一次经历概括企业的全部流程。

下一步应是具体动作：复现某个错误、补一个概念、练一次项目介绍，而不只是“下次更自信”。公开经验时去除未授权内容、个人联系方式和具体面试官身份。
