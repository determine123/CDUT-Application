# 寻找实习与投递复盘

> 整理：2026-10-03。通用建议、个人经历与政策分开阅读；当年官方文件优先。

用职位要求判断匹配，记录岗位、来源、技能、投递时间、状态与下一步。少量试投帮助定位问题，之后针对性调整，未回复不代表已知拒绝原因。

面试前确认工作地点、每周到岗、持续时间、内容和报酬。与课程、科研、毕业任务分别核对，重要条件保留书面记录。

作者曾因答辩与现有工作冲突错过面试，也因通勤和到岗要求退出机会。借鉴的是核实条件与复盘的方法，而不是投递数量或单家公司评价。

从[成理就业信息](https://cdutjy.cdut.edu.cn/)与单位官方招聘页核查。项目能否公开需单独获得许可，不为介绍岗位先支付不明费用。

## 把岗位要求拆成可核对的内容

保存投递时的岗位描述和来源日期，分别标出明确要求、可加分项与尚未说明的条件。对每项要求写自己已有的证据，例如相关课程、能运行的项目、一次问题定位或团队协作记录；没有证据的项就记为缺口，不把“接触过”写成已经熟练掌握。

如果岗位写“熟悉机器学习”，可以准备一个自己能解释数据、基线、评价指标和失败实验的项目；如果写“工程开发”，就准备一次需求、实现、测试和运行说明。材料按照实际岗位调整，不为满足所有描述临时堆积无法解释的技术名词。作品整理可参考[项目证据](project-proof.md)和[简历检查](resume.md)。

## 个人投递记录模板

以下记录保存在自己的笔记中。完整简历、招聘方联系方式和面试材料无需公开到本手册。

```text
单位 / 岗位 / 工作地点：
职位来源、岗位编号与查看日期：
主要职责与明确要求：
已有证据与尚缺的能力：
投递日期、渠道、简历版本：
当前状态：已投递 / 测评 / 面试 / 待反馈 / 已明确拒绝 / 已获结果 / 自己退出
反馈来源与日期：
面试或沟通时间：
到岗时间、每周安排和持续时间（已确认 / 待确认）：
工作内容、指导方式和其他重要条件（已确认 / 待确认）：
与课程、答辩或科研的冲突：
下一步及跟进日期：
```

同一单位的不同岗位分开记录；招聘方明确要求不要重复投递时按其说明处理。收到结果后更新状态，不把没有回复统一归为拒绝，也不要把邀请面试记成已获实习。跟进频率按招聘方提供的安排设定，消息没有新增事实时避免重复催问。

## 用一次小复盘决定下一步

少量试投后，先检查可观察到的问题：投递入口是否正确、岗位是否仍开放、简历是否讲清相关经历、时间条件是否冲突。进入面试后，记录被问到而无法展开的问题，并回到代码、笔记或课程资料补证据；不凭“感觉答得不错”推断拒绝原因。

下一轮尽量选择一项明确调整，例如更换与岗位相关的项目说明，或补上作品的运行步骤，并记录版本。这样可以比较不同阶段的反馈；样本很少、岗位不同或流程不一致时，不把变化算成某一改法的成功率，也不凭投递数量判断个人能力。

## 接受之前核对能否履行安排

把课程、考试、答辩、团队任务和可到岗时间放在同一日历中。招聘沟通中的“可以协调”要进一步问清具体安排及确认主体，向自己的学校或团队核实需要履行的手续。条件尚未确定时说明自己的实际约束，不先承诺无法完成的到岗时间。

核对工作内容、报酬与结算安排、办公地点、必要设备和入职材料，保存对方正式提供的文件。要求先转账、提供无关账号或提交超出合理范围的资料时，先通过已知官方渠道核实。具体合同或制度问题向负责主体询问，本手册的经验描述不代替正式约定。

## 实习过程中留下可交接的成果

开始任务时确认交付物、验收方式、依赖和反馈渠道。每周记录已完成内容、验证结果、当前阻碍和需要协助的事项；需求变化时同步更新范围，不只记录工作时长。

结束前按团队要求整理交接说明：功能现状、运行方式、测试范围、已知问题和后续建议。公司代码、数据、账号和内部文档留在获准的环境中；公开作品集只写被允许披露的内容，不把内部成果复制到个人仓库。简历中的数字来自可核对且允许使用的记录，没有授权时可描述本人承担的工作范围与验证方法。

## 经验投稿怎样让后来者用得上

写明年份、当时的专业与准备、寻找机会的渠道、需要协调的时间条件、实际工作和最终阶段。说明哪些内容是自己的观察，哪些来自岗位文件；不公开面试官私人信息、保密题目或内部材料。一段解释自己为何接受或退出的经历，通常比仅列单位名称更有参考价值。
